# Промты для оркестратора
## Шаблоны промтов для управления пайплайном разработки

---

## 📋 Промт 1: Создание глобального плана

Используй когда начинаешь новый проект или добавляешь большую фичу.

```
Ты опытный Архитектор и Senior Unity Developer. Создай детальный план для игры [НАЗВАНИЕ ИГРЫ].

## Требования к плану:
1. Декомпозируй на независимые шаги (каждый шаг — отдельная механика/система)
2. Каждый шаг должен быть самодостаточным и тестируемым
3. Добавь stub-ы для интерфейсов между модулями, чтобы шаги можно было реализовывать независимо
4. Укажи порядок реализации с учётом зависимостей
5. После создания plan.md будет READ-ONLY

## Архитектурные требования:
- Используй MVP паттерн (Model-View-Presenter)
- Model и Presenter — чистый C#, тестируемый без Unity
- View — MonoBehaviour, реализует интерфейс
- Service Locator для глобальных сервисов
- Entry Point для инициализации

## Контекст:
- @AI/UNITY_MVP_ARCHITECTURE_GUIDE.md — архитектурные паттерны
- @AI/UNITY_TDD_GUIDE.md — тестирование

## Формат ответа:
1. Задай вопросы с вариантами ответов (до 20 за раз)
   Формат: "N. Вопрос? → A) вариант ← recommended, B) вариант, C) вариант"
2. После получения ответов создай AI/plan.md

## Что должно быть в plan.md:
- Обзор архитектуры (диаграмма)
- Список модулей с ответственностями
- Stub-ы интерфейсов для каждого модуля
- Порядок реализации шагов
- Точки интеграции между модулями
```

## 📋 Промт 2: Детализация шага (через оркестратор)

Используй когда нужно детализировать конкретный шаг из плана.

```
Ты оркестратор. Детализируй шаг [N] из @AI/plan.md.

## Правила работы:
1. Используй @agent-unity-architect для создания step_{N}.md
2. Если архитектор задал вопросы — передай мне как есть, жди ответ
3. Мой ответ "1A, 2B" передай агенту как "Ответы: 1A, 2B"
4. После завершения покажи резюме и спроси "Продолжить к реализации?"

## Обязательные секции в step_{N}.md:
1. Components — список компонентов (Model, View, Presenter)
2. Interfaces — интерфейсы для View
3. Implementation Specs — полный код каждого компонента
4. Test Specs — unit-тесты для Model и Presenter
5. Scene Setup Script — Editor скрипт для настройки сцены
6. Validation Checklist — чеклист для проверки

## Контекст для архитектора:
- @AI/plan.md — глобальный план
- @AI/UNITY_MVP_ARCHITECTURE_GUIDE.md — архитектура
- @AI/UNITY_TDD_GUIDE.md — тестирование

## После создания step_{N}.md:
Покажи:
- Количество компонентов
- Количество тестов
- Список файлов к созданию

Не переходи к реализации без моего подтверждения.
```

## 📋 Промт 3: Реализация шага (через оркестратор)

Используй когда step_{N}.md готов и нужно реализовать код.

```
Ты оркестратор. Реализуй шаг [N] из плана.

## Правила работы:
1. Используй @agent-unity-programmer для реализации
2. Источник истины: @AI/step_{N}.md (и ТОЛЬКО он)
3. Программист должен создать ВСЕ файлы из спецификации
4. Никаких отклонений от плана

## Что должно быть создано:
- Runtime код (Models, Views, Presenters)
- Интерфейсы
- Тесты в Tests/EditMode/
- Scene Setup скрипт в Editor/

## Контекст для программиста:
- @AI/step_{N}.md — детальная спецификация
- @AI/UNITY_MVP_ARCHITECTURE_GUIDE.md — паттерны

## После реализации:
1. Покажи список созданных файлов
2. Спроси "Запустить валидацию?"

Не переходи к валидации без моего подтверждения.
```

## 📋 Промт 4: Валидация шага (через оркестратор)

Используй после реализации кода для проверки.

```
Ты оркестратор. Валидируй шаг [N].

## Правила работы:
1. Используй @agent-unity-mcp для взаимодействия с Unity
2. НЕ используй MCP инструменты напрямую — всё через агента

## Последовательность валидации:
1. Проверить консоль на ошибки компиляции (read_console)
2. Дождаться окончания компиляции (editor_state)
3. Запустить Scene Setup (execute_menu_item: "Setup/Step {N}")
4. Запустить тесты (run_tests: testFilter="Step{N}")
5. Дождаться завершения тестов
6. Проверить результаты

## Контекст для MCP агента:
- @AI/UNITY_MCP_GUIDE.md — справочник по MCP

## Ожидаемый результат:
- ✅ PASSED — все проверки пройдены, можно переходить к следующему шагу
- ❌ FAILED — список проблем для исправления

## При ошибках:
Верни мне детальный отчёт:
- Тип ошибки (компиляция/тесты/сцена)
- Конкретные сообщения об ошибках
- Рекомендации по исправлению

Не переходи к следующему шагу при ошибках.
```

## 📋 Промт 5: Полный цикл шага (автоматический)

Используй для автоматизации полного цикла одного шага.

```
Ты оркестратор. Выполни полный цикл для шага [N].

## Последовательность:
1. ДЕТАЛИЗАЦИЯ: @agent-unity-architect создаёт step_{N}.md
   → Если вопросы — передай мне, жди ответ
   → После завершения — покажи резюме
   
2. РЕАЛИЗАЦИЯ: @agent-unity-programmer реализует код
   → Строго по step_{N}.md
   → Покажи список созданных файлов
   
3. ВАЛИДАЦИЯ: @agent-unity-mcp проверяет результат
   → Компиляция → Scene Setup → Тесты
   → Покажи результат

## Переходы между этапами:
- После детализации спроси: "Step_{N}.md готов. Реализовать?"
- После реализации спроси: "Код создан. Валидировать?"
- После валидации:
  - ✅ Успех: "Шаг {N} завершён. Перейти к шагу {N+1}?"
  - ❌ Ошибки: "Найдены проблемы. [список]. Исправить и повторить?"

## Контекст:
- @AI/plan.md
- @AI/PIPELINE_GUIDE.md
- Все гайды агентов

Начни с детализации шага {N}.
```

## 📋 Промт 6: Исправление ошибок

Используй когда валидация нашла проблемы.

```
Ты оркестратор. Исправь ошибки в шаге [N].

## Обнаруженные проблемы:
[ВСТАВЬ ОШИБКИ ИЗ ВАЛИДАЦИИ]

## Правила:
1. Если ошибка в ЛОГИКЕ (неправильная реализация):
   → Используй @agent-unity-programmer для исправления
   → Программист смотрит на step_{N}.md и ошибку
   
2. Если ошибка в СПЕЦИФИКАЦИИ (неправильный план):
   → Сначала спроси меня, нужно ли менять план
   → Изменение step_{N}.md требует моего подтверждения
   
3. Если ошибка в ТЕСТАХ:
   → Проверь, тест правильный или код неправильный
   → Исправь нужную часть

## После исправления:
1. Покажи что было изменено
2. Запусти валидацию повторно через @agent-unity-mcp

Не считай шаг завершённым до успешной валидации.
```

## 📋 Промт 7: Обзор плана (список шагов)

Используй для просмотра прогресса.

```
Ты оркестратор. Покажи статус плана из @AI/plan.md.

## Формат вывода:
Для каждого шага покажи:
- Номер и название
- Статус: ⬜ Не начат | 📝 Детализирован | 💻 Реализован | ✅ Валидирован
- Файлы (если есть): step_{N}.md, созданные .cs файлы

## Пример:
```
📋 План: Match3 Game

1. Grid System          ✅ Валидирован
   └─ step_1.md, GridModel.cs, GridView.cs, GridPresenter.cs
   
2. Element Spawning     💻 Реализован (ожидает валидацию)
   └─ step_2.md, SpawnerModel.cs, SpawnerView.cs
   
3. Swap Mechanics       📝 Детализирован
   └─ step_3.md
   
4. Match Detection      ⬜ Не начат

5. Falling Animation    ⬜ Не начат
```

## Рекомендации:
- Какой шаг следующий?
- Есть ли блокеры?
```

Детализируй шаг N через @agent-unity-architect

Реализуй шаг N через @agent-unity-programmer
```

### Валидировать шаг
```
Валидируй шаг N через @agent-unity-mcp
```

```
Полный цикл для шага N: детализация → реализация → валидация
