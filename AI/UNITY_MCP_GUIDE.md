# Unity MCP Guide
## Руководство по работе с Unity через MCP

---

## 📋 Обзор

Unity MCP (Model Context Protocol) позволяет взаимодействовать с Unity Editor программно:
- Проверять состояние компиляции
- Читать консоль
- Запускать тесты

**Важно:** Scene Setup выполняет пользователь вручную через меню Unity.

---

## 🔧 Инструменты для валидации

### 1. read_console
Читает сообщения из Unity Console.

```json
{
  "action": "read_console"
}
```

**Возвращает:**
- Ошибки компиляции
- Warnings
- Debug.Log сообщения
- Результаты тестов

**Использование:**
```
Проверка компиляции:
1. Вызови read_console
2. Ищи "[Error]" или "CS" коды
3. Если есть ошибки — компиляция не прошла
```

### 2. run_tests
Запускает тесты в Unity Test Runner.

```json
{
  "action": "run_tests",
  "testMode": "EditMode",
  "testFilter": "Step1"
}
```

**Параметры:**
| Параметр | Значения | Описание |
|----------|----------|----------|
| testMode | "EditMode", "PlayMode" | Тип тестов |
| testFilter | string | Фильтр по имени (опционально) |

**Важно:**
- Тесты выполняются асинхронно
- После запуска нужно дождаться завершения
- Проверяй результаты через `read_console`

---

## 📊 Ресурсы (Resources)

### editor_state
Текущее состояние редактора.

```json
{
  "isPlaying": false,
  "isPaused": false,
  "isCompiling": false,
  "activeScene": "Game.unity"
}
```

### tests
Список доступных тестов.

### project_info
Информация о проекте.

## 🔄 Workflow: Валидация шага

### Последовательность действий

```
┌─────────────────────────────────────────────────────┐
│               VALIDATION WORKFLOW                    │
├─────────────────────────────────────────────────────┤
│                                                      │
│  1. CHECK COMPILATION                                │
│     └─► read_console                                 │
│         └─► Есть ошибки? → STOP, вернуть список     │
│                                                      │
│  2. WAIT FOR COMPILATION                             │
│     └─► editor_state.isCompiling                    │
│         └─► true? → Подождать, повторить            │
│                                                      │
│  3. RUN TESTS                                        │
│     └─► run_tests(testFilter: "StepN")              │
│         └─► Запускает асинхронно                    │
│                                                      │
│  4. WAIT FOR TESTS                                   │
│     └─► Повторять read_console                      │
│         └─► Искать "All tests passed" или ошибки   │
│                                                      │
│  5. REPORT RESULTS                                   │
│     └─► ✅ Все тесты прошли                         │
│     └─► ❌ Список failed тестов                     │
│                                                      │
│  ⚠️ SCENE SETUP — ПОЛЬЗОВАТЕЛЬ ДЕЛАЕТ ВРУЧНУЮ       │
│                                                      │
└─────────────────────────────────────────────────────┘
```

### Пример сессии

```
>>> Проверяю компиляцию...
[read_console]
Результат: Нет ошибок

>>> Запускаю тесты...
[run_tests: testMode="EditMode", testFilter="Step1"]
Результат: Тесты запущены

>>> Ожидаю завершения...
[read_console] (через 2 сек)
Результат: "Running tests..."

[read_console] (через 2 сек)
Результат: "All tests passed: 5/5"

>>> ✅ Компиляция OK, тесты OK
>>> Теперь запусти в Unity: Setup → Step 1
```

## ⚠️ Обработка ошибок

### Ошибки компиляции

```
[Error] CS0246: The type or namespace 'IPlayerView' could not be found
```

**Действия:**
1. Остановить валидацию
2. Вернуть список ошибок
3. Указать файлы с проблемами

### Failed тесты

```
[FAIL] PlayerModelTests.TakeDamage_WhenDead_DoesNothing
Expected: 0
But was: -10
```

**Действия:**
1. Собрать список failed тестов
2. Включить сообщения об ошибках
3. Вернуть отчёт

### Timeout тестов

Если тесты не завершаются более 60 секунд:
1. Проверить editor_state
2. Возможно PlayMode завис
3. Предложить перезапуск

---

## 📝 Шаблон валидации

```
Валидируй шаг {N}.

1. read_console → проверить ошибки компиляции
2. Если isCompiling → ждать
3. run_tests(testFilter: "Step{N}")
4. Ждать 2-5 сек
5. read_console → проверить результаты
6. Повторять п.5 пока тесты не завершатся
7. Вернуть отчёт

⚠️ НЕ запускать execute_menu_item — Scene Setup делает пользователь!
```

---

## 🔒 Ограничения

1. **Асинхронность тестов**
   - Тесты запускаются асинхронно
   - Нужно polling через read_console
   
2. **Компиляция**
   - Во время компиляции команды могут не выполняться
   - Жди editor_state.isCompiling = false

3. **Scene Setup**
   - MCP НЕ настраивает сцену
   - Пользователь запускает Setup/Step N вручную

---

## 🎯 Правила для MCP агента

### DO ✅
- Проверяй компиляцию первой
- Жди завершения тестов
- Возвращай чёткий статус: ✅ PASSED или ❌ FAILED
- Сообщай пользователю запустить Scene Setup

### DON'T ❌
- Не запускай тесты при ошибках компиляции
- Не запускай execute_menu_item для Scene Setup
- Не считай валидацию завершённой без результатов тестов
- Не игнорируй failed тесты

---

## 📊 Статусы валидации

| Статус | Описание | Следующий шаг |
|--------|----------|---------------|
| ✅ PASSED | Компиляция OK, тесты OK | Пользователь запускает Scene Setup |
| ❌ COMPILE_ERROR | Ошибки компиляции | Исправить код |
| ❌ TEST_FAILED | Тесты не прошли | Исправить тесты или код |
| ⏳ PENDING | Тесты выполняются | Ждать завершения |

## 📋 Формат отчёта

### При успехе:
```
═══════════════════════════════════════
STEP N: VALIDATED ✅
═══════════════════════════════════════

КОМПИЛЯЦИЯ:  ✅ OK
ТЕСТЫ:       X/X passed

Теперь запусти в Unity: Setup → Step N
```

### При ошибке:
```
═══════════════════════════════════════
STEP N: FAILED ❌
═══════════════════════════════════════

КОМПИЛЯЦИЯ:  ❌ [или ✅]
ТЕСТЫ:       X/Y passed

Ошибки:
- [детали]
```
