## 🎯 Ключевые принципы

### 1. Простота превыше всего
**SOLID, DRY, KISS — без переусложнений.**
- Минимально достаточные решения
- Не абстракции ради абстракций
- Понятный код важнее "умного" кода

### 2. Изоляция контекста
Каждый агент работает в **чистом контексте** — не смешивайте агентов в одном разговоре.

### 3. Документы как источник истины
- `plan.md` — READ-ONLY после создания
- `step_{N}.md` — полная спецификация для шага
- Агенты не импровизируют — следуют документам

### 4. Обязательное тестирование
- Каждый шаг включает тесты
- MCP Agent валидирует компиляцию и тесты
- Пользователь проверяет сцену вручную

### 5. Разделение ответственности валидации
- **MCP Agent:** компиляция + тесты (автоматически)
- **Пользователь:** настройка сцены + визуальная проверка (вручную)

## 📋 Фаза 1: Архитектура (unity-architect)

**Вход:** Номер шага из `plan.md`

**Выход:** `step_{N}.md` содержащий:

```markdown
## Step {N}: {Name}

### 1. Components
- ComponentA (Model) — описание
- ComponentB (Presenter) — описание
- ComponentC (View) — описание

### 2. Interfaces
```csharp
public interface IComponentAView { ... }
```

### 3. Implementation Specs
[Полный код каждого компонента]

### 4. Test Specs
```csharp
// ComponentAModelTests.cs
[TestFixture]
public class ComponentAModelTests
{
    [Test]
    public void Method_Condition_ExpectedResult() { ... }
}
```

### 5. Scene Setup Script
```csharp
// Editor/Step{N}SceneSetup.cs
public static class Step{N}SceneSetup
{
    [MenuItem("Setup/Step {N} - {Name}")]
    public static void Setup()
    {
        // 1. Создать/открыть сцену
        // 2. Очистить сцену (удалить старые объекты)
        // 3. Создать GameObject-ы
        // 4. Добавить компоненты (View, MonoBehaviour)
        // 5. Настроить ссылки между объектами
        // 6. Создать/настроить ScriptableObject конфиги
        // 7. Подключить конфиги к компонентам
        // 8. Настроить камеру/освещение если нужно
        // 9. Сохранить сцену
    }
}
```

**Требования к Scene Setup:**
- Полностью автономный — запустил и всё готово
- Идемпотентный — можно запускать повторно
- Создаёт ВСЕ объекты с нуля (не полагается на существующие)
- Настраивает конфиги (ScriptableObject) если они нужны
- Сохраняет сцену после настройки

### 6. Expected Scene Result

**Hierarchy:**
- [GameObject Name] — компоненты: ComponentA, ComponentB
- [GameObject Name] — компоненты: ...

**Inspector (для главного объекта):**
- Field1: значение
- Field2: ссылка на X
- Config: Assets/Configs/StepNConfig.asset

**Scene View:**
- [Визуальное описание: что видно, где расположено]

**Console:**
- Нет ошибок
- [Опционально: ожидаемые логи]

**Как проверить работоспособность:**
1. Нажми Play
2. Сделай X
3. Должно произойти Y

### 7. Validation Checklist
- [ ] Компиляция без ошибок
- [ ] Все тесты проходят
- [ ] Сцена настроена корректно
- [ ] Play Mode работает как описано
```

## 📋 Фаза 2: Реализация (unity-programmer)

**Вход:** `step_{N}.md`

**Выход:**
- Все `.cs` файлы по спецификации
- Тесты в `Tests/EditMode/`
- Scene Setup скрипт в `Editor/`

**Правила:**
- Код 1:1 со спецификацией
- Никаких "улучшений" или отклонений
- Файлы < 200 строк
- Простота превыше всего

---

## 📋 Фаза 3: Валидация

### 3.1 Автоматическая (unity-mcp-agent)

**Вход:** Запрос на валидацию шага N

**Действия:**
1. `read_console` — проверить ошибки компиляции
2. `run_tests` — запустить тесты для шага
3. Дождаться завершения тестов
4. Проверить результаты

**Выход:**
- ✅ Шаг валидирован — можно настраивать сцену
- ❌ Ошибки — список проблем для исправления

### 3.2 Ручная (пользователь)

**Действия:**
1. Запустить `Setup/Step {N}` из меню Unity
2. Проверить сцену по `Expected Scene Result`
3. Запустить Play Mode и проверить работоспособность
4. Сообщить о проблемах если есть

**Выход:**
- ✅ Всё соответствует — можно переходить к следующему шагу
- ❌ Проблемы — описать что не так

## 📝 Главный промт: @step N

**Использование:** `@step N` — запускает полный цикл для шага N.

```
@step N

Полный цикл для шага N:

1. ДЕТАЛИЗАЦИЯ
   → Task(unity-architect): создать AI/step_{N}.md
   → Показать резюме
   → Ждать подтверждения

2. РЕАЛИЗАЦИЯ
   → Прочитать Parallel Execution Plan из step_{N}.md
   → Task(unity-programmer) × N параллельно по группам
   → Показать созданные файлы
   → Ждать подтверждения

3. ВАЛИДАЦИЯ (автоматическая)
   → Task(unity-mcp): компиляция + тесты
   → Показать результат

4. НАСТРОЙКА СЦЕНЫ (ручная)
   → Пользователь запускает Setup/Step {N}
   → Пользователь проверяет Expected Scene Result
   → Пользователь сообщает о проблемах или подтверждает

Между этапами ждать подтверждения пользователя.
```

### ОБЩЕЕ
- ✅ **Простота превыше всего: SOLID, DRY, KISS — без переусложнений**
- ✅ Минимально достаточные решения
- ❌ Не усложняй без необходимости

### ДЛЯ АРХИТЕКТОРА

- ✅ Проверяй только компиляцию и тесты
- ✅ Дожидайся завершения тестов
- ✅ Проверяй ВСЕ тесты шага

## 🔧 Troubleshooting

### Проблема: Тесты не запускаются
```
1. Проверь asmdef — тесты должны ссылаться на Runtime
2. Проверь namespace — должен совпадать с asmdef
3. Проверь атрибуты [TestFixture], [Test]
```

### Проблема: Scene Setup не в меню
```
1. Скрипт должен быть в Editor/ папке
2. Класс должен быть static
3. Метод должен иметь [MenuItem("...")]
4. Перекомпилируй проект (Ctrl+R)
```

### Проблема: Scene Setup создаёт не то
```
1. Проверь Expected Scene Result в step_{N}.md
2. Сравни с тем что создалось
3. Опиши разницу для исправления
```

### Проблема: MCP не подключается
```
1. Проверь Window > MCP for Unity
2. HTTP Server должен быть запущен
3. Проверь статус подключения
```
